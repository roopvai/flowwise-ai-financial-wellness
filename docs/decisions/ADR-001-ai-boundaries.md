# ADR-001: Separate Deterministic Financial Logic from Generative AI

**Status:** Accepted  
**Date:** September 22, 2026

## Context

FlowWise provides customers with financial insights using transaction,
balance, income, expense, and recurring-obligation data.

The product also includes a generative AI assistant that allows customers
to ask questions such as:

- Can I afford a $700 vacation?
- How is my cash flow this month?
- What is my largest spending category?
- What is my credit score?

A key architecture decision was determining whether the LLM should
perform financial calculations itself or whether those calculations
should be performed by deterministic application logic.

## Decision

FlowWise will separate financial computation from generative AI.

### Deterministic Python Layer

Python is responsible for calculating:

- Income
- Expenses
- Net cash flow
- Recurring obligations
- Available-to-spend amount
- Planned-purchase impact
- Remaining available cash
- Adjusted cash flow

These calculations are treated as verified financial context.

### Generative AI Layer

The LLM is responsible for:

- Explaining calculated results
- Summarizing financial information
- Answering natural-language questions
- Identifying when available data is insufficient
- Creating a conversational customer experience

The LLM is not the system of record for financial calculations.

## Example

Customer asks:

> Can I afford a $700 vacation?

FlowWise first calculates:

Available to spend: $2,042  
Planned purchase: $700  
Remaining available: $1,342  
Adjusted monthly cash flow: $905

These verified values are then supplied to the AI.

The AI explains what the results mean rather than independently
calculating them.

## Why This Decision Was Made

### Reliability

Financial calculations require predictable behavior.

The same financial inputs should produce the same numerical output.

### Hallucination Risk

Generative models can produce unsupported information.

Separating calculations from generation reduces the possibility of
AI-generated financial values being treated as authoritative.

### Explainability

The application can show which values were calculated by FlowWise and
which content was generated by AI.

### Auditability

Deterministic calculations can be independently reproduced and reviewed.

### Graceful Degradation

Core FlowWise functionality remains available if the external AI
service becomes unavailable.

For example, the dashboard and financial calculations can continue
operating even when the AI explanation service cannot complete a
request.

## Alternatives Considered

### Option 1: Allow the LLM to Perform All Calculations

Advantages:

- Simpler initial implementation
- Less application logic

Disadvantages:

- Reduced predictability
- Greater hallucination risk
- Harder to audit
- Harder to distinguish calculated facts from generated content

This option was rejected.

### Option 2: Deterministic Calculations + AI Explanation

Advantages:

- Predictable financial calculations
- Better auditability
- Reduced hallucination exposure
- AI still provides conversational value
- Core functionality does not depend on AI availability

Disadvantages:

- Additional application logic
- Structured context must be passed between the calculation and AI layers

This option was selected.

## Guardrails

The AI layer is instructed to:

- Use only supplied financial context
- Avoid inventing balances, transactions, income, debt, or credit data
- Avoid performing new financial calculations
- Identify when insufficient information is available
- Avoid presenting itself as a financial advisor
- Avoid recommending specific investments or financial products
- Explain limitations when appropriate

## Validation

Two prototype scenarios were used to validate the design.

### Supported Question

Customer:

> Can I afford a $700 vacation?

Python calculated the purchase impact and provided the verified values
to the AI for explanation.

### Unsupported Question

Customer:

> What is my credit score?

Because credit-score information was not available in the supplied
context, the AI indicated that there was insufficient information
rather than generating a credit score.

## Consequences

This architecture creates a clear boundary:

**Python = financial computation and source of truth**

**Generative AI = explanation and conversational interface**

Future AI capabilities should follow the same principle unless a new
architecture decision explicitly changes this boundary.
